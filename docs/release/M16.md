# M14–M16 SDK release evidence

Implementation: resident point-to-plane/point-to-point/GICP CUDA objectives and exact covariance neighborhoods; owning inspection reference context; bounded parallel normal/boundary and comparison queries; immutable size/device-based automatic selection with explicit overrides and actual-backend reporting. Public contracts remain C++20, millimetres, scan-to-reference transforms, owned results and Result error boundaries. No new third-party product dependencies were added.

## Verification

- Windows/MSVC CPU Debug and Release: 36/36 each. CUDA Debug and Release: 38/38 each.
- Linux GCC 11.4 Release: 36/36 and installed consumer. Clang 21.1.8 Debug with ASan+UBSan/leak detection: 36/36.
- Generated file acceptance: 200 runs across Windows CPU/CUDA, AVX2-disabled CPU, Linux GCC and Clang. Cross-platform inputs match SHA-256 and business results satisfy exact discrete/1e-5 floating gates.
- AVX2-off and restored-on builds passed; GPU Compute Sanitizer memcheck/leaks, racecheck and synccheck report zero errors/hazards/leaks.
- Format-check and configured static analysis retained. GCC signed-conversion/shadow warnings were fixed without suppressions. A missing Clang OpenMP runtime is now a configure-time error; an old Clang 14 ASan startup defect was reproduced independently and resolved with an upstream-fixed compiler runtime, with ASLR unchanged.

## Performance and limits

Million-point four-worker complete inspection: CPU/GPU one-shot P50 4687/3091 ms; reused-reference P50 3369/1751 ms. Million-point GICP reused registration: CPU/GPU 3456/289 ms. GPU iteration packets are 360 bytes. Full reports preserve preparation costs, sample counts, P95, raw timings and limitations: [GPU](../benchmarks/PCAD-GPU-003.md), [inspection](../benchmarks/PCAD-PIPEPERF-003.md), [generated acceptance](../validation/PCAD-VALID-001.md).

The automatic threshold is a conservative warm-registration heuristic from one host, not a universal end-to-end speed guarantee. Reference comparison trees are rebuilt per inspection. Voxel sampling is not inserted into the inspection path; clustering remains scalar based on measured cost on the documented fixtures. No GPU memory-peak improvement is claimed. Industrial/site accuracy, more physical hardware, cold-start latency and broad GPU architecture deployment remain separate gates. CUDA presets target the local native GPU; distributors must explicitly build/test their deployment architectures.

## SDK compatibility

The version remains 0.1.0; rebuild C++ consumers after the documented M11–M13 parameter-layout changes. `InspectionContext` and `RegistrationContext::backend()` are exported. GPU JSON `execution_scope` now describes `gpu_resident_objective_cpu_solve`; matching consumers must accept that value. CPU default behavior and JSON quantitative metric semantics remain unchanged. SDK packages include new reports/raw evidence and the standard-library-only fixture generator. The public include root stays `include/pointcloud_ad/` and exposes no third-party/device types.

Linux installation now sets target-scoped relative RPATHs: the CLI locates the package library directory through `$ORIGIN`, and the SDK library locates private shared dependencies beside itself. This fixes the relocated archive CLI startup failure without `LD_LIBRARY_PATH` or absolute build/library paths. The installed-CLI check is also part of Linux CI.

## Package verification

Windows CPU and CUDA SDK ZIP packages passed installation, standalone consumer builds, relocated consumers and isolated runtime checks using:

```powershell
pwsh ./scripts/build.ps1 -Preset windows-msvc-release -VerifyInstall -VerifyPackage
pwsh ./scripts/build.ps1 -Preset windows-cuda-release -VerifyInstall -VerifyPackage
```

Linux GCC Release passed installation and standalone consumers against both the installed tree and relocated TGZ. `env -u LD_LIBRARY_PATH <sdk>/bin/pcad --version` and the packaged CLI's generated acceptance passed. Reproduce after the GCC build:

```bash
cmake --install out/build/linux-gcc-release --prefix out/install/linux-gcc-release
cpack --config out/build/linux-gcc-release/CPackConfig.cmake -B out/package/linux-gcc-release
```

The generator and executable from each extracted package passed **32 additional cases**: [Windows CPU, 8](M16-windows-cpu-package.json), [Windows CUDA/auto, 16](M16-windows-cuda-package.json), and [Linux CPU, 8](M16-linux-package.json). These supplement the 200 core acceptance runs. Run the installed `scripts/validate-generated.py` with `--pcad <sdk>/bin/pcad[.exe] --output <data-directory> --threads 4 --backends cpu` (or `gpu auto` for CUDA). Each summary records input and executable hashes. Package archives and SHA-256 files are generated under `out/package/<preset>/`; binaries and datasets are build artifacts, not committed sources.

All verification above was run locally; the updated CI workflow has not been claimed as a remote CI result. Real industrial data and a second physical host were unavailable.
