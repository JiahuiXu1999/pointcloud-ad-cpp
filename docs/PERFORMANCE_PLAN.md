# CPU、SIMD 与 GPU 性能优化计划

## 目标与执行边界

在保持毫米单位、右手坐标、scan-to-reference 变换、Result 错误边界和检测判定语义的前提下，优化完整检测耗时、连续扫描吞吐量及内存使用。
当前授权实施 M11–M13；M14–M16 仅规划。每次只推进一个原子任务，记录测试、构建及可复现基准后再进入下一项。默认部署为 Windows/Linux x64，GPU 使用可选 NVIDIA CUDA；无 GPU 时保留完整 CPU 实现。

## 实施结果

M11–M13 的九个原子任务已按顺序完成，逐项证据保存在 `docs/tasks/`，状态见 `docs/ROADMAP.md`。最终构建、正确性回归、性能收益及限制见[验收与性能报告](benchmarks/PCAD-SIMD-003.md)。10 万点四线程单次配准相对原始单线程基线耗时下降约 28%/31%/45%；SIMD 单独的端到端增益尚不稳定。百万点完整检测已实际运行通过。M14–M16 仍待实施。

## M10 基线起点

M10 已提供 CPU/CUDA 三种配准目标、精确 GPU 对应点搜索和参考上下文。CPU 优化器仍串行，每轮重新分配变换/查询缓冲；GPU 仅搜索，查询点和对应索引每轮跨设备传输；GICP 协方差和方程累加仍在 CPU。完整 InspectionPipeline 尚不复用参考预处理。

## CPU 方案

先复用临时缓冲，再使用上下文拥有的有界工作线程。独立上下文独立拥有资源，同一上下文由调用方串行调用。线程预算包括调用线程；不修改进程级线程策略。查询临时区线程私有，输出按原索引写回。目标函数固定分块且固定合并顺序，分块不随线程数变化。GICP 每点独立计算并保持邻域排序与退化规则。

## SIMD 方案

保留可强制选择的标量参考路径，先支持 AVX2。检测 CPU 和 OS 寄存器状态支持；仅 AVX2 实现目标使用专用编译选项。默认路径不能包含不受支持的指令。优先向量化变换和规则算术，计入打包成本，避免只统计内核时间。公开点云布局不改变。AVX-512/ARM NEON 另立任务。

## GPU 后续方案

每帧上传扫描数据后，在 GPU 完成变换、对应点搜索、过滤、残差、权重、雅可比和确定性归约；只传回小规模方程和统计量，先保留 CPU 6×6 求解。之后测量是否需要 GPU 求解、流重叠或 CUDA Graph。参考协方差复用，扫描协方差每帧重算。设备资源不得暴露到公开 API。精确匹配的等距规则、GICP 正则化和退化语义必须保留。

## 数值与正确性

同一实现/设备重复运行必须可重复；固定算术策略的 CPU 不同线程数结果必须一致。标量与 SIMD 优先保持运算顺序，禁止用 fast-math 换取未经验证的结果变化。固定块归约相对旧串行累加的舍入变化必须有事先定义的误差预算和旧结果回归，不得削弱已有测试。跨后端比较区分毫米、弧度和无量纲指标；阈值边界、等距、重复点、掩码及退化情况必须独立验证。最终验收集的检测判定必须一致。

## 基准协议

覆盖单次调用、参考复用、变化扫描；小型、10 万和百万点；平面、曲面、不同密度/噪声及参考扫描数量不等。完整大规模检测可用命令选项启用，必须明确实际运行过的规模，不能把百万点搜索等同于百万点检测。计时排除数据生成及正确性检查，包含准备、传输和释放；记录构建、硬件、采样数、P50/P95，避免并行基准相互干扰。性能目标依据基线制定，不承诺统一加速比。当前合成测量不能证明工业精度或生产节拍。

## 完成标准

每项任务包含实现、行为测试、文档和 Windows CPU Debug/Release 验证；公共接口/安装变化验证 Release 独立 consumer。涉及 CUDA 的共享求解改动运行 CUDA Debug/Release 回归。保持 warnings-as-errors、格式检查和静态分析；资源生命周期的 GPU 变更补充 Compute Sanitizer。新依赖需要 ADR 和固定 vcpkg manifest，本阶段不引入依赖。
